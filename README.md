# 赛博山寺 · Cyber Sansa

一个在本地独立运行的中文赛博佛寺。进入首页即加载法堂，点地面或用 `WASD` 走动，可以合掌、礼佛、敲木鱼、拨念珠、上香，也可以走到右侧问心席向师父问事求签，或绕池到对岸的许愿树下挂牌许愿。

复刻参考 [Cyber Sansa](https://sansatemple.live/)。

> **素材版权提示**：本项目的佛像扫描与诵经录音保留了原始署名与许可说明（见下方「素材来源」）。其余取自参考站的场景模型、贴图与字库，其再分发许可尚未逐项核实。本仓库用于技术学习与本地对照，请勿用于商业用途。

## 特性

**法堂与多人共处**
- Three.js 实时渲染的法堂、莲池、月光庭院，昼夜场景切换
- WebSocket 多人同步：同一房间可见其他访客的位置、姿态与合掌问候
- 每房 24 人，掉线释放坐垫，重连自动归位

**问心席**
- 与师父自由对话，支持佛学问答、人生解惑与追问
- 摇签 → 掷筊 → 解签 → 存入签匣的完整求签流程，含 3D 签筒与杯筊交互
- 观音百签底本，100 个连续签号，保留签等、签诗、典故题名与传统解曰
- 接入 DeepSeek 时走真实 AI；未配置密钥时回落到带来源标注的知识卡，功能不中断

**许愿树**
- 绕池寻路到树下，写下心愿后红木牌升起挂上树枝
- 心愿卡片保存在浏览器本地，可回读、可定位对应木牌

**全场景精修（v1）**
- Blender 生成 188 个网格的倒角/细分几何，77 种 PBR 材质分别调整
- 可在设置中随时开关，与原场景对照；资产加载失败自动回退

## 快速开始

需要 **Node.js 22** 或更新版本。

```sh
npm ci
npm start
```

打开 http://127.0.0.1:4183/ 。用 `PORT` 和 `HOST` 可覆盖默认的 `127.0.0.1:4183`。

点击地面或用 `WASD`、方向键移动，拖动环顾四周。验证多人时，请开两个独立窗口或浏览器配置——同一浏览器的标签页节能可能暂停后台渲染。

### 启用真实 AI（可选）

```sh
cp .env.example .env.local
```

在 `.env.local` 填入密钥后重启服务：

| 变量 | 用途 |
|---|---|
| `DEEPSEEK_API_KEY` | 启用真实对话、解签与追问。留空时显示标注过的知识卡或传统解曰，求签与签匣照常可用 |
| `DEEPSEEK_BASE_URL` | 默认 `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | 默认 `deepseek-flash` |

密钥仅由服务端读取，不会进入前端产物。`.env.local` 已在 `.gitignore` 中，不会被提交。

## 项目结构

```
server.mjs              启动入口、静态资源、房间目录、多人 WebSocket
consultation/           服务端：DeepSeek 对接、中文检索、求签状态、百签数据
public/consultation/    问心席前端：对话、签匣、场景器物、3D 预览、样式
public/refinement/      精修几何与材质（来自 Blender 的可逆替换包）
public/assets/          原站构建产物、模型、贴图、字库、音频
tools/refinement/       Blender 精修流水线与浏览器验收脚本
```

## 验收与测试

```sh
npm test
```

覆盖房间分配与 24 人上限、状态与动作同步、坐垫互斥、退出清理、百签顺序与字段、确认前领签限制、重试幂等、旧签兼容、读签与追问、DeepSeek 流式响应模拟。

浏览器端验收脚本位于 `tools/refinement/`，需要另行安装 Playwright：

| 脚本 | 覆盖范围 |
|---|---|
| `smoke.cjs` | 精修模型替换、蒙皮与骨骼不变、原版恢复、键盘行走 |
| `ritual-flow.cjs` | 礼佛、对话、摇签、掷筊、领签、解签、保存 |
| `wish-flow.cjs` | 绕池寻路、许愿、挂牌、卡片保存与重读 |
| `mobile.cjs` | 390×844 触摸交互 |
| `fallback.cjs` | 精修资产 503 时回退原场景 |

> 无头浏览器（headless / SwiftShader 软件渲染）下 3D 场景加载会长时间卡住，验收与性能取样请使用 `headless: false` 或带 GPU 的环境。

## 已知边界

- 访客、房间与进行中的求签状态保存在服务进程内，重启即清空
- 对话记忆、已存签文与语言选择保存在浏览器本地存储，换设备或端口即各自独立
- 部署到其他环境需运行 Node 服务；经反向代理时需转发 `/presence` 的 WebSocket 升级，并允许问心席接口逐步下发响应
- 精修版本的性能取样来自本机单视角，尚未做低端移动设备长时测试
